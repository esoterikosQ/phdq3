# P2. 한국어 패처 프로젝트 — 상세 실행 계획

> 목적: 한국어에 최적화된 바이트 엔트로피 모델(패처)을 학습하고, 이를
> (1) 한국어 패칭 특성 분석, (2) 엔트로피 탐지 기반 detect-then-correct GEC,
> (3) P1 파인튜닝용 패처 ablation의 세 갈래로 활용한다.
>
> 선행 조건: 없음 (P1과 독립 병행 가능. 단 P2-3만 P1 완료 후)
> 예상 기간: P2-1: 3–5주, P2-2: 4–8주, P2-3: 2–3주
> 산출물: 한국어 엔트로피 모델 체크포인트, 패칭 분석 리포트(논문 기여 1),
>          탐지 기반 GEC 결과(논문 기여 2), 패처 ablation 결과

핵심 설계 원칙: "패치를 표준 패칭에 맞게 수정"하는 직접 교정은 성립하지
않는다(패칭은 분할이지 복원 가능한 표현이 아님). 패처의 역할은 **오류 탐지와
국소화**로 한정하고, 교정은 별도 메커니즘(국소 생성 또는 후보 rescoring)이
담당한다. LM-Critic/BIFI 계열의 critic-fixer 구조와 동형.

원칙:
- 토크나이저·특수토큰·엔트로피→패치 규칙은 **BLT와 완전 호환**으로 구현한다
  (vocab 260, BOS/EOS ID 동일, threshold/monotonicity 규칙 동일).
  이 호환성의 의미: 바이트 토크나이저는 학습되는 것이 아니라 "UTF-8 바이트 값
  → ID"의 고정 매핑이므로, 매핑 일치 검증은 언어적 행동의 비교가 아니라
  **기계적 인터페이스 호환성** 검증이다. blt-1b의 바이트 임베딩 테이블이
  legacy ID 체계에 결박되어 있으므로, 매핑이 어긋나면 P2-3의 패처 주입
  (같은 텍스트 → 같은 ID 열 위에서의 경계 계산, entropy 가중치 교체)이
  성립하지 않는다.
- 호환성 테스트 fixture는 **P2가 자체 생성한다** (legacy 코드 리딩으로 매핑·
  세그멘테이션 규칙을 명세화한 뒤 그 명세를 기준으로). P1 A-3의 dump가 이미
  있으면 재사용해도 되지만 이는 편의이지 의존이 아니다 — P2-1·P2-2는 P1 진행
  상황과 무관하게 착수 가능하다.
- 학습은 클러스터 1:55 제한을 전제로 checkpoint resume을 1급 기능으로 구현한다.

## P2-1: 한국어 엔트로피 모델 학습 + 패칭 분석 (3–5주)

### 1-1. 코퍼스 파이프라인 (3–5일)

**작업 내용**

1. 소스 선정과 라이선스 기록 (`ko_patcher/corpus/SOURCES.md`):
   - 한국어 위키피디아 최신 dump (CC BY-SA)
   - 모두의말뭉치 중 사용 승인된 부분 (신문/문어/구어 — 계정·약관 확인)
   - (선택) HF 공개 한국어 웹 코퍼스 — 품질 필터 강하게
   - 목표 규모: 정제 후 5–20GB 텍스트 (엔트로피 모델은 수십 M 파라미터이므로
     이 규모로 충분. 원본 blt-entropy의 학습 규모를 참고치로 조사·기록)
2. `clean.py` 구현:

```text
- 인코딩: UTF-8 강제, 잘못된 바이트 시퀀스 행 제거
- 문서 단위 정제: HTML/마크업 제거, 제어문자 제거(개행·탭 제외)
- 품질 필터: 한글 비율 < 20% 문서 제거(단 한영 혼합 분석용 서브셋은 별도 보존),
  반복 문자열 비율, 최소/최대 길이
- 중복 제거: 문서 단위 exact hash → (여유 시) MinHash near-dup
- held-out 분리: 학습에 절대 넣지 않는 분석용 세트를 먼저 떼어냄
  (analysis_heldout/: 위키 1%, 뉴스 샘플, GEC val의 정답문 등)
  ★ GEC 데이터(native/learner/union)의 어떤 split도 사전학습에 넣지 않는다 —
    P2-2의 탐지 평가가 오염되기 때문
```

3. `pack.py`: 문서를 `<EOS>` 구분자로 연결 → 고정 길이 바이트 청크(예: 8192)
   → memmap 또는 .bin shard로 저장. terashuf 없이 numpy 셔플로 충분한 규모.

**실행 작업**: 로그인 노드 또는 CPU job에서 실행. 산출 통계(문서 수, 바이트 수,
한글/ASCII/기타 바이트 비율)를 `corpus/STATS.md`에 기록.

### 1-2. 모델·토크나이저 구현 (3–5일)

**작업 내용**

1. `tokenizer.py`: `text.encode('utf-8')` + 특수토큰 오프셋. legacy
   `BltTokenizer`와 ID 매핑 완전 일치 테스트 (`test_ko_tokenizer.py`).
2. `model.py`: 표준 causal byte LM. 두 설정 준비:

```yaml
entropy_small:   # 개발/디버깅
  dim: 512,  layers: 8,  heads: 8,  params: ~25M
entropy_base:    # 본 학습 — facebook/blt-entropy 설정을 조사해 동급으로 맞춤
  dim: 768,  layers: 14, heads: 12, params: ~100M  # 조사 후 확정
공통: RMSNorm, SwiGLU, RoPE, SDPA causal. FlexAttention/xFormers 불필요
```

3. `patching.py`:

```python
def next_byte_entropy(model, byte_ids) -> Tensor:      # H(p(next|ctx)) per position
def segment(entropies, threshold, max_patch=8, ...) -> list[int]:
    # BLT의 경계 규칙(threshold 초과 시 새 패치, max_patch 강제 분할 등)을
    # legacy 코드와 동일하게 재현. approx_monotonic 등 변형 규칙도 옵션으로.
```

**테스트**: 로직과 모델을 분리해서 검증한다.
- 토크나이저: 명세화된 매핑(바이트 값 + offset, 특수토큰 ID) 기준의 자체
  fixture로 왕복 일치 검증. legacy 코드 리딩으로 명세를 확정하며, P1 A-3
  dump가 있으면 교차 확인에 활용(의존 아님).
- 세그멘테이션: 인공 entropy 배열을 주입 → 기대 경계 산출 일치. 즉 "같은
  entropy 값이 주어졌을 때 규칙이 같은 경계를 내는가"를 모델과 무관하게 검증.

### 1-3. 사전학습 (1–2주, 대부분 큐/학습 대기)

### 1-4. 패칭 분석 (1–2주) — 논문 기여 1

**작업 내용** (각각 독립 스크립트, held-out 데이터만 사용)

1. `entropy_profile.py`:

```text
- 위치 유형별 엔트로피 분포: 한글 음절 1/2/3번째 바이트, ASCII, 공백 직후,
  문장부호 직후, 어절 경계
- 가설 검증: 음절 내부(2,3번째) 엔트로피 ≪ 음절 경계 — 히스토그램/박스플롯
- 산출: figures/entropy_by_position.pdf + 수치 표
```

2. `threshold_sweep.py`:

```text
- threshold ∈ [0.5, 3.0] sweep → 평균/최대 패치 길이, bytes-per-patch 분포
- 원본 논문 기준(영어 평균 4바이트)과 비교: 같은 평균 패치 길이를 얻는
  한국어 threshold는 얼마인가
- global model step 수 프록시(= patch 수/byte 수) 계산 → 연산량 함의
```

3. `morpheme_alignment.py`:

```text
- 형태소 분석기(mecab-ko 또는 kiwipiepy — 클러스터 설치 가능성으로 결정)로
  held-out 텍스트 분석 → 형태소 경계 바이트 위치 집합
- 패치 경계와의 정합: precision/recall (패치 경계가 형태소 경계인 비율,
  형태소 경계가 패치 경계로 잡히는 비율), threshold별 곡선
- 어절(공백) 경계와의 정합도 별도 산출 — SpaceByte식 규칙 대비 우위 논거
```

4. `crosslingual_compare.py`:

```text
- 동일 held-out에 대해 {원본 blt-entropy, 한국어 패처} 패칭 비교
- 영어 텍스트/한국어 텍스트/한영 혼합 각각에서 평균 패치 길이, 경계 위치 diff
- 한영 혼합 문장에서 코드 전환 지점의 엔트로피 스파이크 관찰
```

**완료 기준**: 4개 분석 리포트 + figure. "한국어에서 엔트로피 패칭이 어떻게
행동하며, 영어 최적 threshold가 왜 부적합한가"에 대한 정량 답변.

## P2-2: 엔트로피 탐지 기반 detect-then-correct GEC (4–8주)

### 2-1. 탐지기 구현 (1–2주)

**작업 내용** — `ko_patcher/gec/detect.py`

```python
@dataclass
class DetectionResult:
    spans: list[tuple[int, int]]   # byte 단위 오류 후보 구간
    scores: list[float]
    signals: dict                   # 신호별 원값 (분석용)

def detect(model, text, cfg) -> DetectionResult:
    # 신호 1: 엔트로피 스파이크 — H_i가 문맥 이동평균 + kσ 초과
    # 신호 2: surprisal — -log p(실제 다음 바이트) 가 임계 초과
    #   (엔트로피는 "불확실"을, surprisal은 "실제 관측이 이상"을 잡음.
    #    오타 탐지에는 surprisal이 더 직접적 — 두 신호 모두 구현해 비교)
    # 신호 3: 패치 구조 이상 — 정상 코퍼스 대비 비정상적으로 짧은 패치 연속
    # 후처리: 인접 신호 병합 → span, 한글 문자 경계로 스냅,
    #          최소/최대 span 길이 제한
```

**작업 내용** — `ko_patcher/gec/eval_detect.py`

```text
- 정답: GEC 데이터의 M2 gold edit span (KAGAS 산출 .m2의 A 라인 →
  토큰 span → 바이트 span 변환기 필요. 변환기 단위 테스트 필수)
- 지표: span-level P/R/F1 (부분 겹침 인정 기준을 명시: overlap ≥ 1 byte /
  IoU ≥ 0.5 두 기준 병기), 문장 수준 오류 유무 분류 AUC
- False positive 분석: 무오류 문장(target==source)에서의 오탐율,
  고유명사/신조어 오탐 사례 수집 (정성 표)
- 비교 조건: {surprisal, entropy, 패치 이상, 결합} × {원본 패처, 한국어 패처}
```

**실행 작업**: native val에서 threshold/신호 조합 튜닝 → native test는 최종
1회만. learner/union으로 일반화 확인.

**완료 기준**: 탐지 성능표. 이 수치가 나쁘면(예: F1 < 0.4) P2-2의 교정 단계를
축소하고 탐지 분석 자체를 기여로 전환하는 결정 지점.

### 2-2. 교정기 A — 후보 rescoring (noisy-channel) (1–2주)

탐지 span에 대해 편집 후보를 생성하고 엔트로피 모델 likelihood로 선택한다.
학습이 필요 없어 먼저 구현한다 (베이스라인 겸 빠른 검증).

**작업 내용** — `candidates.py` + `correct_rescore.py`

```python
# 후보 생성 (span 내부만):
#   - 자소 수준 교체: 인접 자판(두벌식) 오타 표, 유사 발음 자모 표
#   - 띄어쓰기: 공백 삽입/삭제 (한국어 GEC 최다 유형)
#   - 조사 교체: 은/는, 이/가, 을/를, 와/과 등 폐집합
#   - 삭제/중복 제거
# 탐색: span당 후보 ≤ K(예: 50), 다중 span은 독립 가정 또는 beam
# 선택: score = log p_LM(문장 with 후보) - λ·edit_cost
#   λ로 precision/recall 트레이드오프 제어 (val에서 튜닝)
# 무편집 옵션 항상 포함 (원문 유지가 최고점이면 교정하지 않음 → precision 방어)
```

### 2-3. 교정기 B — 국소 infilling 생성 (2–3주)

**작업 내용** — `correct_infill.py`

```text
옵션 B1 (우선): P1의 파인튜닝된 BLT-GEC 모델을 재사용하되, 출력을 탐지
  span 주변으로 제약 — 전체 문장을 생성시키고 탐지 span 밖의 편집은

```

### 2-4. 통합 평가 (1주)

**작업 내용** — `scripts/eval_ko_gec.sh` + 결과 정리


## P2-3: 한국어 패처 × BLT 파인튜닝 ablation (P1 완료 후, 2–3주)

**작업 내용**

1. `blt_hf` 파이프라인에서 패처 주입 지점 확인 (P1 A-3의 코드 리딩 결과 활용):
   HF 구현이 patch_lengths 외부 입력을 받으면 `ko_patcher.patching.segment`
   출력을 주입, 내부 patcher 고정이면 entropy model 가중치 교체 경로 구현.
2. 조건: {원본 패처, 한국어 패처(영어와 평균 패치 길이를 맞춘 threshold),
   한국어 패처(한국어 최적 threshold)} × blt-1b 파인튜닝 (native 우선)
3. `ablation/patch_stats.py`: 학습·평가 전 구간에서 평균 패치 길이,
   patch/byte 비율(global model 연산량 프록시), 수렴 곡선 기록
4. 주의 — 분포 이동: blt-1b는 원본 패처의 패치 분포로 사전학습됨. 패처 교체
   초기 loss 상승과 흡수 속도 자체가 관찰 대상. 학습 초기 500 step의 loss를
   고해상도로 로깅.

**완료 기준**: 3조건 비교표 (GLEU/F0.5 + 연산량 프록시 + 수렴 속도).
"한국어 패처가 품질 또는 효율에서 이득이 있는가"에 대한 답.
