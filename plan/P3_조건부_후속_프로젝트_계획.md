# P3. 조건부 후속 프로젝트 — 상세 실행 계획

> P3은 세 개의 독립 프로젝트(P3a, P3b, P3c) 묶음이며, 각각 **명시적 트리거
> 조건**이 충족될 때만 착수한다. 트리거 판정 자료는 P1이 산출한다.
>
> - P3a: Patch-aware incremental generation cache — 트리거: P1 A-6 + C-2
> - P3b: C++ M2 scorer 이식 — 트리거: P1 D-3
> - P3c: 이식성 우선 커스텀 byte LM — 트리거: 논문 스코프 결정 (전략적)
>
> 공통 원칙: 트리거 미충족 시 착수하지 않는다. "만들 수 있다"는 착수 사유가
> 아니다. 각 프로젝트는 착수 시점에 이 문서의 계획을 재검토해 갱신한다.

# P3a. Patch-aware Incremental Generation Cache

## 트리거 조건 (둘 다 충족 시에만 착수)

```text
(i)  P1 A-6 cache probe의 고장 깊이 판정이 "(다) 깊은 부재"일 것 —
     즉 cache 미동작의 원인이 얕은 버그(P1 범위에서 blt_hf/patched/ 모듈로
     수정 가능·수정 완료)가 아니라, patcher/encoder/global/decoder의
     증분 상태 관리 자체가 존재하지 않는 경우일 것
(ii) P1 C-2 실측: batched no-cache 최고 처리량으로도 전체 평가(2633문장)가
     소수 job으로 완료 불가 (여전히 수십 shard 필요)
```

얕은 수정과 P3a는 대립하는 선택지가 아니라 같은 스펙트럼이다. 얕은 고장
((나) 판정)은 P1이 흡수하며, P3a는 "수정"이 아니라 증분 상태의 설계·구현이
필요한 경우만 담당한다. P1에서 patched 모듈 수정을 시도했다면 그 결과와 실패
지점이 P3a Phase 0의 입력이 된다.

착수 전 필수 확인: Transformers upstream(BLT 관련 PR/이슈)에서 cache 지원이
진행 중인지 확인한다. 진행 중이면 이 프로젝트는 upstream 기여(테스트·리뷰·
패치 제출)로 축소한다. 자체 구현하더라도 최종 산출 형태는 upstream PR을
1순위로 한다 (fork 유지비용 회피).

## 배경과 문제 정의

no-cache generation은 매 바이트마다 전체 prefix에 대해 entropy 계산 → 패칭 →
3단 forward를 재수행한다(시퀀스당 O(L²)). BLT의 incremental state는 일반
KV cache보다 복잡하다:

```text
GenerationState
├── entropy model KV cache            # 표준 causal LM cache
├── 확정된 patch 경계 목록
├── 현재 미완성 patch의 byte ID 버퍼
├── local encoder 상태 (미완성 patch 구간의 byte hidden)
├── global transformer patch-level KV cache
├── local decoder 상태 + byte↔patch cross-attention 매핑
```

핵심 불변식: **global transformer는 새 patch가 확정될 때만 한 step 전진한다.**

사전 검증해야 할 이론적 전제 (Phase 0에서 확정):
- 엔트로피 패칭이 순차 생성에서 인과적(causal)인가 — 위치 i의 패치 경계
  결정이 미래 바이트에 의존하지 않는가. legacy 패칭 규칙(monotonicity 변형
  포함)별로 확인. 인과적이지 않은 규칙이 있으면 incremental 경로에서는
  인과적 변형을 쓰고 full recompute와의 차이를 정량화한다.

## Phase 2: Batching (1–2주)

- 배치 내 시퀀스별 patch 확정 시점이 다름 → global step을 시퀀스별로
  마스킹하거나(패딩 patch), 확정 시퀀스만 모아 global forward (성능 비교)
- EOS 완료 시퀀스 처리: active 압축 vs 자리 유지 — no-cache 경로(P1 C-1)와
  동일 정책 채택
- 테스트: batch=1 결과와 시퀀스별 완전 일치

## Phase 3: Beam (2주)

- parent beam 재정렬 시 모든 cache 텐서를 `index_select`로 재정렬
- copy-on-write 검토: patch-level global cache는 beam 간 공유 구간이 크므로
  실측 후 필요 시 도입 (선최적화 금지)
- 테스트: no-cache batched beam(HF generate)과 최종 출력·score 일치

## Phase 4: 실측 및 운영 통합 (1주)

- P1 C-2와 동일 벤치 grid로 처리량 재측정 → no-cache 대비 배속 보고
- `blt_hf/generation.py`에 `backend="incremental"` 추가, manifest에 기록
- 서로 다른 backend shard의 aggregate 차단은 기존 fingerprint가 담당

## 완료 기준

1. step-wise logits parity (허용 오차 명시), patch 경계·global step 수 일치
2. batch/beam에서 no-cache와 출력 동등
3. no-cache 대비 처리량 개선 정량 보고 (examples/sec, GPU util, peak mem)
4. (가능하면) Transformers upstream PR 제출

예상 규모: 6–9주. 연구 난도 높음.

# P3b. C++ M2 Scorer 이식

## 트리거 조건

```text
P1 D-3 프로파일 결과, 기 구현된 병렬 Python + 문장별 체크포인트 + timeout
pass 체제로 (i) 전체 M2 평가가 운용 가능한 시간 내 미완료 또는
```

설계를 그대로 계승하며, 아래는 실행 순서 중심 요약 + 보강이다.

# P3c. 이식성 우선 커스텀 Byte LM 아키텍처

## 트리거 조건

```text
P1·P2 완료 후, 학위 논문 스코프를 "BLT 적용·분석"에서 "아키텍처 기여"로
확장하기로 결정한 경우. 자동 트리거 없음 — 지도교수와의 스코프 합의가 전제.
```

## 목표와 설계 원칙

BLT의 adaptive compute(엔트로피 기반 동적 패칭)를 유지하되, 이식성 문제를
설계 단계에서 제거한 byte LM. P1(HF 이식 경험)과 P2(한국어 엔트로피 분석)의
산출을 직접 소비하는 프로젝트다.

```text
설계 원칙 (하드 제약):
1. 외부 entropy 모델 제거 → encoder 위 LM head에서 boundary score 직접 계산
   (Scratchpad Patching 방식 — patch 결정과 encoder를 단일 학습 코드로 통합)
2. 동적 shape 제거 → 시퀀스당 boundary 수를 고정 Top-K로 선택해 정적
   computation graph 유지 (ByteFlow 방식 — torch.compile/일반 GPU/미래
   backend 친화)
3. 모든 attention에 eager reference 구현 존재, SDPA는 기본 최적화,
   Flash/Triton은 optional. custom autograd/C++ extension 금지
4. 가변 패치는 padding + mask로 표현 (max_patch_len 고정 텐서)
5. CPU에서 전체 forward/backward correctness 테스트 통과 (CI에 포함)
6. checkpoint는 safetensors
참고 구현: goombalab/hnet (MIT, end-to-end 동적 청킹의 유일한 공개 구현 —
  라우터 설계·학습 안정화 기법 참고. 단 mamba_ssm 의존 부분은 채택 금지),
  MBLM (고정 계층 baseline 구조 참고)
```

## Phase 0: 스코프 및 비교 설계 (1–2주)

**작업 내용**

1. 연구 질문 확정 (예시): "고정 Top-K boundary + 내장 entropy head가
   외부 패처 기반 동적 패칭과 compute-matched 조건에서 동등 이상의 bpb를
   달성하는가 — 특히 한국어에서."
2. 비교 조건 매트릭스:

```text
A. BPE Transformer (compute-matched)         — 토큰 기반 기준선
B. 고정 패칭 byte LM (patch=4 고정)          — adaptive 제거 ablation
C. SpaceByte식 경계 규칙 (P2-1의 어절 정합 데이터로 한국어 규칙 설계)
D. 제안 모델: 내장 entropy head + Top-K boundary
(선택) E. 외부 패처 BLT-소형 재현 — P2 패처 재사용
```

3. 규모 제약 확정: 모델 50–300M, 데이터 5–30GB (P2 코퍼스 재사용 + 확장).
   ★ 대규모(수백 B 바이트) 사전학습은 현 인프라에서 불가 — 스코프에서 배제.
   기여는 소규모 compute-matched 비교 + 한국어 특화 분석으로 구성.

## Phase 1: 코어 구현 (3–4주)

**작업 내용** — 신규 저장소 또는 `PHDQ2/byte_topk/`

```text
1. 공용 블록: RMSNorm/SwiGLU/RoPE/SDPA causal (P2 model.py 재사용·확장)
2. boundary 모듈:
   - encoder 각 위치의 boundary score s_i (LM head entropy 또는 학습된
     scoring head — 둘 다 구현해 ablation)
   - Top-K 선택: k = ceil(L / target_patch_len) 고정 → 항상 동일 shape
   - 미분 가능성: hard Top-K + straight-through vs score를 soft 가중으로
     흘리는 변형 — 학습 안정성 비교 (H-Net의 router 안정화 기법 참고)
3. patch pooling: boundary로 정의된 구간을 cross-attention 또는 mean+proj로
   풀링 → 고정 shape [B, K, D] (padding mask 포함)
4. global transformer: 표준 causal, [B, K, D]
5. local decoder: byte가 자기 patch의 global 출력에 attend — 정적 매핑
   텐서(byte→patch index)로 gather, FlexAttention 불필요하게 설계
6. 테스트: CPU에서 tiny 설정 overfit, boundary gradient 흐름,
   K 경계값(K=1, K=L) 동작, torch.compile 통과(graph break 0 확인)
```
