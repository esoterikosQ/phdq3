- `blt_hf/`는 `reference_code/blt`를 import하지 않는다. 유일한 예외는 Phase A의

  로직은 동작을 검증한 뒤 `blt_hf/`로 독립 이식하고 원본 파일/commit을 기록한다.

  byte IDs, entropy/patch 경계, local/global/cross attention 허용 위치, padding 의미,
  주요 layer hidden state/logits가 사전 정의한 허용 오차를 통과해야 한다.
- 모든 실행 조건(모델 ID, revision, transformers 버전, attn 구현, beam, batch)은
  `manifest.py`를 통해 JSON으로 기록한다.

## Phase A: HF BLT 도입 및 동작 검증 (1–2주)

### A-0. 코드·가중치 provenance 확정 (착수 게이트)

다음 세 주소는 서로 역할이 다르다.

```text
reference code:  https://github.com/facebookresearch/blt
legacy main:     https://huggingface.co/facebook/blt-1b
legacy entropy:  https://huggingface.co/facebook/blt-entropy
HF conversion:   https://huggingface.co/itazap/blt-1b-hf
```

현재 `blt_gec`의 기본값도 main=`facebook/blt-1b`,
entropy=`facebook/blt-entropy`이다. 다만 기본값이 실제 과거 실험값을 증명하지는
않으므로, legacy job의 `train_args.json`, 로그, HF cache snapshot 또는 checkpoint
manifest에서 실제 `blt_repo`, `entropy_repo`, revision을 회수한다. 다른 주소나 로컬
경로를 사용했다면 그 artifact를 기준으로 이하 비교 대상을 변경한다.

`itazap`은 Meta 계정이 아니라 **BLT를 transformers에 포팅한 HF 엔지니어의
개인 계정**이다. 다만 transformers 공식 코드(`configuration_blt.py`)의 참조
checkpoint가 `itazap/blt-1b-hf`로 지정되어 있어 사실상 공식 참조 산출물의
지위를 갖는다. 변환자는 `facebook/blt-1b` 원본과 동일한 가중치라고 명시하지만
이 설명은 provenance의 출발점일 뿐 최종 증명이 아니다 — **A-7-3의 B↔C 텐서
비교가 이를 판정한다** (transformers main에 공식 변환 스크립트가 존재함이
확인되었으므로 직접 변환본 B를 만들 수 있다. A-7 참조). 원본과 변환본의
라이선스 표기가 다르므로 원본 FAIR Noncommercial Research License를 적용
대상으로 간주하고, 사용·파인튜닝·산출물 공개 가능 범위를 실험 전에 기록한다.

**완료 기준**: legacy 실제 실행 artifact ID/revision, HF conversion revision, tokenizer
revision, 라이선스 수락 기록이 `blt_hf/NOTES.md`에 고정됨. 하나라도 불명확하면
"legacy와 동일" 비교를 시작하지 않는다.

### A-2. 모델 로드 및 생성 sanity check

**작업 내용**

`blt_hf_checks/check_load_generate.py` 작성:

```python
import torch
from transformers import AutoTokenizer, BltForCausalLM

MODEL_ID = "itazap/blt-1b-hf"
MODEL_REVISION = "<PINNED_SHA>"  # A-0에서 확정
PROMPTS = [
    "My name is",
    "안녕하세요. 오늘 날씨가",
    "다음 문장을 교정하세요:",   # GEC 유사 프롬프트
]

def main():
    tok = AutoTokenizer.from_pretrained(MODEL_ID, revision=MODEL_REVISION)
    model = BltForCausalLM.from_pretrained(
        MODEL_ID, revision=MODEL_REVISION,
        dtype=torch.bfloat16, device_map="cuda",
        attn_implementation="eager",   # 1차: eager로 correctness 확인
    )
    model.eval()
    for p in PROMPTS:
        inputs = tok(p, return_tensors="pt").to(model.device)
        with torch.no_grad():
            out = model.generate(**inputs, max_new_tokens=64,
                                 do_sample=False, use_cache=False)
        print(f"--- prompt: {p!r}")
        print(tok.decode(out[0]))

if __name__ == "__main__":
    main()
```

**실행 작업**

1. eager로 실행 → 출력이 유의미한 텍스트인지, 한국어 출력이 깨진 UTF-8을 포함하지 않는지 확인.

2. `attn_implementation="sdpa"`로 재실행 → eager와 greedy 출력 token ID가 동일한지 비교 (`torch.equal`). 다르면 그 차이를 기록하고 이후 실험은 한 가지 구현으로 고정한다.

3. bf16 vs fp32 greedy 출력 비교 (V100 사용 가능성 대비 fp16도 확인).

**완료 기준**: eager/sdpa 양쪽에서 유효한 UTF-8 생성, greedy 출력 일치 여부 문서화.

#### A-2-1. itcerdo 5090 호환성 작업 시간·메모리 실측

`blt_hf_checks/bench_compatibility.py`를 일반 Linux command로 실행한다. 학습은 하지 않고
아래 구간을 `time.perf_counter()`와 `torch.cuda.synchronize()`로 분리 측정한다.

```text
1. tokenizer load
2. model load 및 GPU 배치
3. 첫 forward (cold/warm-up)
4. warm forward 10회: 평균/P50/P95
5. greedy generation 64·256·512 bytes: 총 시간, bytes/sec
6. patcher 단독 실행: 입력 길이별 시간
7. cache probe True/False 시간
8. torch.cuda.max_memory_allocated/reserved
```

```bash
# itcerdo 5090; srun/sbatch 사용 금지
conda activate phdq_blt_hf
/usr/bin/time -v python blt_hf_checks/bench_compatibility.py \
  --model-id itazap/blt-1b-hf \
  --model-revision <PINNED_SHA> \
  --output blt_hf_checks/results/itcerdo_5090_compatibility.json
```

최초 다운로드가 포함된 cold run과 `local_files_only=True`인 warm-cache run을 구분하고,
manifest에 GPU 이름, driver, CUDA, PyTorch, Transformers, dtype, attention backend를 기록한다.
`/usr/bin/time -v`의 전체 wall-clock/max RSS와 JSON의 단계별 GPU timing을 함께 보존한다.

**완료 기준**: 5090에서 load/forward/generation/cache probe가 정상 종료하고, 단계별
wall-clock·throughput·peak VRAM이 JSON에 기록됨. optimizer 생성이나 backward는 하지 않음.

### A-3. Patcher 검증 (핵심 검증 1) — 수학적 정의 기준

**A-3-0 (선행): legacy 엔트로피 모델 구성 확인**

```text
- reference_code/blt에서 entropy model의 config를 확인:
  attn_impl, sliding window / local attention 요구 여부

  (a) 표준 causal 요구 → legacy 패칭은 의미상 유효.
```

```python
#   (a) byte_ids 완전 일치 (특수토큰 오프셋 매핑 포함)
```

실제 설정과 일치하는지(A-3-0과 교차 확인)다. 결과를 `blt_hf/NOTES.md`에
기록한다.

### A-4. Attention mask 의미 검증 (핵심 검증 2)

HF local encoder/decoder가 원본의 local block-causal(sliding window + EOS
segment 격리)을 보존하는지 확인한다. legacy 체크포인트가 full-causal
fallback으로 학습된 전례가 있으므로, 이번에는 반드시 코드 레벨에서 확정한다.

**작업 내용**

1. **코드 리딩**: `transformers/models/blt/modeling_blt.py`에서
   - local encoder self-attention의 마스크 생성 함수
   - local decoder self-attention의 마스크 생성 함수
   - cross-attention(byte↔patch)의 마스크 생성 함수
   를 찾아 각각의 허용 조건을 수식으로 정리해 `blt_hf/NOTES.md`에 기록.
   (sliding window 파라미터가 config에 있는지, EOS segment 분리가 구현되어
   있는지, 아니면 단순 causal인지.)

2. **단위 테스트**: `blt_hf_checks/check_attention_mask.py`

```python
# 소형 인공 시퀀스 (예: 길이 24, 중간에 EOS 2개 삽입)로 마스크 텐서를 직접 추출
# 검사 항목 (원본 BLT의 의미 기준):
#   - 미래 위치 차단 (causal)
#   - window(W) 밖 과거 위치 차단
#   - EOS 이전 query가 EOS 이후 key를 참조하지 않음 (역방향도)
#   - batch별 segment 경계 독립성
# HF 구현이 window/segment를 지원하지 않으면 그 사실 자체를 기록
```

3. **판정 분기**:
   - HF가 원본 의미를 보존 → 통과, 다음 단계로.
   - HF가 단순 causal만 구현 → 변환 가중치가 그 mask로 사전학습됐다고 가정하지
     않는다. 원본 local block-causal(window + EOS segment 격리)과 같은 additive mask를
     `blt_hf/patched/` 또는 명시적 subclass에 구현하고, local encoder/decoder 모든
     layer에 실제 전달되는지 hook으로 검증한다. upstream 원본 파일은 직접 수정하지
     않는다.
   - 정확한 mask를 구현하지 않기로 결정하면 해당 결과는 `HF full-causal variant`로만
     분류한다. 이 변형은 "legacy와 동일한 모델" main run을 대체할 수 없고 Phase B의
     main run 진입 조건을 만족하지 않는다.

4. **padding parity를 같은 게이트에 포함**:
   - unpadded batch=1을 기준으로 right-padding 학습 batch와 left-padding 생성 batch 비교
   - 실제 token 위치의 patch_lengths/patch_ids, local/global/cross mask 허용 위치,
     layer hidden state, logits, loss 비교
   - `attention_mask`가 내부 entropy patcher와 byte↔patch cross-attention까지 적용되는지
     확인. 적용되지 않으면 샘플별 unpadded patch 계산 + 외부 `patch_lengths` 주입 또는
     pad-aware patcher/cross mask를 구현
   - 단순 길이 bucket은 padding을 줄일 뿐 제거하지 못하므로 parity 증거로 사용하지 않음

**완료 기준**: 마스크 허용 조건이 수식으로 문서화되고, 단위 테스트가 그
조건을 통과함. main run은 원본 attention mask와 padding 의미가 동일하고,
batch=1 vs batch=N parity가 허용 오차를 통과해야 함.

### A-5. 학습 forward 검증 (핵심 검증 3)

**작업 내용**

`blt_hf_checks/check_train_forward.py`:

```python
#    - GEC 예제 4개를 배치로 구성 (Phase B의 data_adapter 프로토타입 사용)
```

**완료 기준**: 4예제 overfit 성공(loss < 0.05), 세 컴포넌트 모두 grad 흐름,
padding 처리 방식 문서화.

### A-7. 직접 변환 트랙: 가중치 변환·검증 + 라이선스 확인

**확인된 사실 (2026-09-01)**:
- legacy 저장소(`facebookresearch/blt`)의 `bytelatent/hf.py`는 legacy 클래스
  로딩용이며 `BltForCausalLM` 변환기가 아니다.
- **transformers 저장소 main 브랜치에 공식 변환 스크립트가 존재한다**:
  `src/transformers/models/blt/convert_blt_weights_to_hf.py` (~490줄).
  `facebook/blt-{1b,7b}`의 원본 config·weights와
  `entropy_model/params.json`, `entropy_model/consolidated.pth`를 내려받아
  **메인 모델 + entropy patcher를 하나의 통합 HF checkpoint로 병합**한다.
  즉 변환 코드를 백지에서 작성할 필요는 없고, 이 스크립트를 기반으로 삼는다.
- 단, 이 스크립트는 **release tag(v5.16.1 등)와 pip 패키지에는 포함되지 않고
  main에만 있다**. 따라서 main의 특정 commit SHA에서 파일을 vendoring하여
  `blt_hf_checks/vendor/convert_blt_weights_to_hf.py`로 저장소에 넣고 출처
  commit을 기록한다. main 기준 코드가 설치된 5.16.1 클래스와 API가 어긋나면
  vendored 사본을 수정하고 diff를 남긴다.
- 스크립트에는 **검증 로직(assert/allclose/coverage)이 없다.** 변환의 정확성
  검증은 전적으로 우리 몫이며, 그것이 A-7의 본체다.

**A-7-1: 직접 변환 (B 생성)**

```python
# B(직접 변환본) vs C(itazap/blt-1b-hf, pinned revision):
```

**A-7-4: 계층화된 forward parity (A↔B)**

legacy 환경(A100)의 local encoder/decoder는 full-causal fallback이므로,

```text
층 2 — 마스크 의미가 양쪽에서 같은 컴포넌트의 forward parity:
   entropy patcher (A-3-0에서 표준 causal 확인 시),
   global transformer (양쪽 모두 causal)
   → legacy fixture(A100) vs B(동일 A100) hidden/logits allclose
층 3 — local encoder/decoder: "짧은 입력 트릭"으로 마스크 차이를 소거한

   없는 입력에서는 local block-causal ≡ full causal이므로,
   이 fixture에서의 hidden state 불일치는 곧 변환 오류다.
   ★ window/EOS 의미 자체는 원본 xformers 환경 없이는 end-to-end 검증이
   불가능하다 — A-4의 수학적 정의 기반 단위 테스트가 유일한 검증 수단이며,
   이 한계를 NOTES.md에 명시한다
```

fixture는 A-3-2의 patch_inputs를 재사용하되 층 3용으로 "512바이트 미만 +
EOS 없음" 서브셋을 별도 표기한다. legacy dump는 A100에서, B 실행은 동일
A100에서 수행해 GPU 아키텍처 변수를 제거한다 (5090은 층 1·호환성 테스트만).

**A-7-5: 라이선스**

- B는 외부 공개하지 않는다 (변환물 재배포 권한 불명확 — 로컬 artifact로만)

**완료 기준**: A-7-2 전 항목 통과, A-7-3 판정 기록, A-7-4 층 2·층 3(짧은

### B-1. 데이터 어댑터

**작업 내용** — `blt_hf/data_adapter.py`

```python
MAX_SEQUENCE_LENGTH = 2048

def encode_pair(tok, source: str, target: str, max_length: int) -> GecEncoding:

    ...

def collate(batch, pad_id) -> dict:

    # right-padding, attention_mask, 외부 patch_lengths/pad-aware masks를 함께 생성하고
```

**실측 길이 기준** — 2026-08-28 현재 `data/Preprocessed`의 canonical 9개 split


모든 job 시작 시 동일 통계를 다시 계산하고 최대값이 2,048을
넘으면 자동 절단하지 않고 job을 실패시킨다. 빈 줄은 union train/val/test에 각 1개이며
