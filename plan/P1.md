## 작업 트랙 구조

**2026-09-16 사용자 결정으로 이전의 전체 동질성 게이트를 폐기한다.** 연구 질문은
“Meta BLT-1B 사전학습 가중치를 HF Transformers BLT 구조로 변환하고, 구현 변경을
명시한 뒤 한국어 GEC로 파인튜닝했을 때 어떤 교정 성능을 얻는가”다.
원본 실행과의 hidden state/logits 일치나 기존 BLT와의 성능 동등성을 주장하지 않는다.

변환 관련 추가 검증은 다음 두 가지로 한정한다.

1. **가중치 검사(A-7)**: 모든 원본 텐서의 대응·shape·dtype·값 보존, fused slice,
   누락·충돌, 변환 산출물 hash와 strict loading. 값 비교는 exact equality다.
2. **attention mask 검사(A-4)**: 미래 차단, window, EOS 구간, global 및 byte↔patch
   연결을 독립 규칙으로 검사하고 실제 B의 모든 해당 계층에 전달되는지 확인한다.
   허용 위치와 차단 값은 정확히 비교한다. 원본 runtime이나 부동소수점 허용오차는 불필요하다.

인코딩·패처 동작·label shift·gradient·tiny overfit·생성·지표·재현성 검사는
학습과 성능 평가의 유효성을 위한 일반 필수 테스트로 유지한다. 이를 원본과의
동질성 검증으로 분류하지 않는다. cache/처리량 검사는 P3 판단 자료다.

```text
[1] 고정 소스 → 직접 변환 B → HF 로드·실행 설정 고정 (itcerdo)
       ├─ 가중치 보존 + 실제 attention mask 검사 (학습 없이 itcerdo)
       └─ 인코딩·메모리·backward 구동 준비 → 파인튜닝 (사용자가 neuron에서 실행)
[2] 필요한 학습·생성·채점 검사를 갖추고 native/learner/union 전체 split 평가
[3] GLEU/M2 및 재현 조건 보고, 결과와 발견된 문제를 근거로 다음 실험 계획
```

파인튜닝은 별도 변환 검증 완료를 기다리지 않고 구동 준비 후 진행한다. 다만
실제 가중치 오류·미래 정보 누출·잘못된 label/채점 등 실험을 무효화하는 결함은
영향 범위를 판정하고 수정한다. 수정한 run은 새 ID로 분리하며 기존 증거를 보존한다.
원본 수치 동질성을 입증하지 않았다는 이유만으로 학습 결과를 폐기하거나 C/D를
보류하지 않는다. 낮은 성능도 유효한 실험 결과로 보고한다.

검증 상태는 `weight_checks`, `attention_mask_checks`, `training_checks`,
`evaluation_checks`를 각각 `passed|failed|not_run`으로 기록한다. 전체 동질성의
`pending/confirmed/not_confirmed` 승격 체계는 사용하지 않는다. 과거 JSON의
상태는 당시 기록으로 보존하고 새 범위의 보고서를 연결한다.

`showappl`을 확인하고 새 comment 형식 `field=<허용 field>;appl=pytorch`를 사용한다.


- 기본적인 코드 작성 작업 및 작동 검증과 결과 데이터 취합, 평가, 수정 후 재작업 계획 수립은 gsm과 yellowstone에서 수행

**완료 기준**: 5090과 A100에서 import 오류 없음, CUDA 인식, BLT 클래스 로드 성공.

### A-2. 모델 로드 및 생성 sanity check

직접 변환본 B를 `check_load_generate.py`로 검사한다. C 다운로드는 필요 없다.
실제 loading info에 missing/unexpected/mismatched/error가 없어야 하며, 유한
logits/loss 및 generation 실행을 확인한다. 단일 shift CE와 HF loss를 비교한다.

eager/SDPA의 greedy 차이는 기록하며 실행 backend는 eager로 고정했다. 생성이
실행됐다는 사실과 올바른 UTF-8 종료·GEC 품질을 구분한다. 64-token 예산으로
UTF-8 글자 중간에서 종료된 기존 사례는 일반 생성 wrapper의 종료 정책에서 다룬다.

정상적인 출력 종료·배치 생성 검사는 C-1, 교정 성능은 D에서 평가한다.

### A-3. Patcher 동작 테스트 — 일반 구현 검사

원본 entropy 신경망 forward를 별도 재구현하거나 legacy 출력과 수치 일치를
증명하는 작업은 수행하지 않는다. 현재 HF 구현에 명시한 패칭 규칙을 독립 scalar
구현과 비교해 off-by-one·batch 오염·threshold dtype 처리를 검사한다.

- 본문 byte ID는 byte+4, BOS=1/EOS=2. 학습·생성 인코딩은 B-1 계약을 따른다.
- 패치 시작점은 0, 1 및 `i>0`에서 `entropy[i]>threshold`인 `i+1`.
  마지막 끝점은 `S+1`이며 다음 토큰 예측 슬롯을 포함한다.
- entropy는 같은 dtype에서 `logp=log_softmax(logits)`, `-sum(exp(logp)*logp)`.
- bf16 비교의 유효 threshold와 설정 실수값을 구분해 기록한다. 현재 설정
  `1.335442066192627`은 bf16에서 `1.3359375`로 비교된다. 이를 원본과의 동질성
  허용오차로 사용하지 않는다.
- `check_patch_parity.py`라는 기존 파일명은 유지하되, 같은 HF logits에서 패칭 산술을
  검사하는 범위임을 명시한다. 독립 원본 신경망과의 비교로 해석하지 않는다.
- 패딩·cache는 현재 지원하지 않는다. 무패딩 단건 또는 동일길이 배치만 사용한다.

**완료 기준**: 설정한 패칭 규칙의 단위 테스트와 fixture 검사. 과거 v4 실패와 v5
수정·통과 기록을 모두 보존하며 원본 전체 forward 검증의 선행 단계로 취급하지 않는다.

### A-4. Attention mask 검사 — 변환 후 구현의 필수 검사

`check_attention_mask.py`는 실제 B 가중치를 로드하고 모든 entropy/local encoder/
global/local decoder self-attention 및 encoder/decoder cross-attention의 입력 마스크를
hook으로 검사한다. 기대값은 production mask 함수를 호출하지 않는 독립 구현으로 만든다.
근거는 고정된 Meta/HF 소스에서 확인한 규칙이며 원본 실행 출력은 필요하지 않다.

1. **local/entropy**: `k<=q`, `q-k<512`, `segment(q)==segment(k)`의 교집합.
   `segment(i)=i 이전 EOS 개수`; EOS 자신은 닫는 구간에 속한다.
2. **global**: EOS를 포함한 patch에서 구간을 닫으며 같은 구간의 과거/현재 patch만 허용.
3. **encoder cross**: 해당 patch에 속한 byte만 허용, query를 `cross_attn_k`배 확장.
4. **decoder cross**: 첫 patch 길이를 제외한 예측 위치 대응으로 global patch를 선택,
   key를 `cross_attn_k`배 확장. pooling→global→decoder 연결을 통해 미래 byte가
   현재 예측에 도달하지 않는지 검사한다.
5. **검사 입력**: EOS·연속 EOS·행별 경계가 다른 배치, 길이 511/512/513,
   실제 데이터 최대 길이 1380 및 한도 2048, 가상 다음 patch·오른쪽 0길이 patch.
6. **판정**: 모든 계층의 전체 허용 행렬이 정확히 일치하고 허용값 0, 차단값
   dtype 최솟값 또는 -inf, 누락 hook 0건. 미래/window/EOS 위치를 고의로 연
   마스크를 실패시키는 음성 테스트도 실행한다. 부동소수점 allclose 판정은 사용하지 않는다.

빈 encoder cross query의 finite-min softmax는 전체 byte를 참조할 수 있다고
보수적으로 취급하고, 그 상태가 활성 decoder 예측에 도달하지 않는지 확인한다.
EOS 규칙은 각 self-attention의 격리 규칙이다. hash n-gram·patch pooling까지
포함한 여러 문서 간 완전한 상태 격리를 증명하는 것이 아니므로 **문서 packing은
사용하지 않는다**. 일반 GEC는 샘플당 한 문장 쌍, EOS는 끝에만 삽입한다.

현재 지원 범위는 `attention_mode=osc`, eager, bf16, no-cache, 무패딩 입력이다.
padding/cache는 fail-fast한다. 지원 범위를 넓히면 해당 mask 및 batch 동작 검사를
추가한 뒤 사용한다. 이름 `osc` 자체가 원본 실행의 동질성 인증을 뜻하지 않는다.

**완료 기준**: 실제 B의 전 계층 마스크·미래 연결 검사와 음성 테스트 통과,
artifact·코드·설정 hash를 가진 새 보고서 보존. A100에서는 사용자가 같은 검사로
지원 환경을 확인한다. GPU 간 logits/token 일치를 필수 조건으로 두지 않는다.

### A-6. KV cache 동작 probe (P3a 판정 입력)

**작업 내용**

`blt_hf_checks/check_cache_probe.py`:

```python

```

**고장 깊이 판정** (probe 결과에 반드시 포함):

```text
(가) 정상: use_cache=True가 동작하고 출력이 no-cache와 일치
     → cache 사용을 기본값 후보로 검토. P3a 불필요
(나) 얕은 고장: cache 로직은 존재하나 generate 경로에서 비활성화되어 있거나
     사소한 버그 (코드 리딩으로 원인 특정 가능)
     → P1 범위 내에서 수정한다: modeling_blt.py를 blt_hf/patched/로 복사

       관리. 원본 대비 diff를 NOTES.md에 기록, no-cache 출력과의 parity
       테스트 필수, upstream 이슈/PR 지향. site-packages 직접 편집은 금지
(다) 깊은 부재: patcher/encoder/global/decoder의 증분 상태 관리 자체가 없음
     → "수정"이 아니라 설계·구현의 영역. P3a 스코프로 이관
```

얕은 수정과 P3a는 대립 선택지가 아니라 같은 스펙트럼이며, 이 probe가 고장의
깊이를 판정한다.

**완료 기준**: (a)(b)(c) 결과 + 깊이 판정((가)/(나)/(다))이

### A-7. 직접 변환 트랙: 가중치 변환·검증 + 라이선스 확인

**확인된 사실 (2026-09-01)**:
- legacy 저장소(`facebookresearch/blt`)의 `bytelatent/hf.py`는 legacy 클래스
  로딩용이며 `BltForCausalLM` 변환기가 아니다.
- **transformers 저장소 main 브랜치에 공식 변환 스크립트가 존재한다**:
  `src/transformers/models/blt/convert_blt_weights_to_hf.py` (~490줄).
  `facebook/blt-{1b,7b}`의 원본 config·weights와
  `entropy_model/params.json`, `entropy_model/consolidated.pth`를 내려받아
  **메인 모델 + entropy patcher를 하나의 통합 HF checkpoint로 병합**한다.
  즉 변환 코드를 백지에서 작성할 필요는 없고, 이 스크립트를 기반으로 삼는다.
- 단, 이 스크립트는 **release tag(v5.16.1 등)와 pip 패키지에는 포함되지 않고
  main에만 있다**. 따라서 main의 특정 commit SHA에서 파일을 vendoring하여
  `blt_hf_checks/vendor/convert_blt_weights_to_hf.py`로 저장소에 넣고 출처
  commit을 기록한다. main 기준 코드가 설치된 5.16.1 클래스와 API가 어긋나면
  vendored 사본을 수정하고 diff를 남긴다.
- 스크립트에는 **검증 로직(assert/allclose/coverage)이 없다.** 변환의 정확성
  검증은 전적으로 우리 몫이며, 그것이 A-7의 본체다.

**A-7-1: vendored 스크립트 수정 (변환 실행 전 필수)**

upstream 스크립트를 원문 그대로 실행하면 안 된다. 코드 확인 결과 다음 결함이
있으며, vendored 사본에서 수정하고 diff를 `blt_hf_checks/manifests/vendor.diff`로
보존한다.

```text
1. revision 미지원: --revision 인자가 없고 4개의 hf_hub_download()가 모두
   model_id의 기본 revision을 사용 → --model-revision을 추가해 4개 호출에
   전달하고 CLI 필수 인자로 처리한다. 이것 없이는 sources.lock의 SHA가 실제 변환 입력을 보증하지 못한다
2. entropy 소스: 스크립트는 facebook/blt-entropy가 아니라 facebook/blt-1b
   저장소 내부의 entropy_model/{params.json,consolidated.pth}를 받는다.
   선택한 entropy 입력과 revision을 별도로 명시하고 hash를 보존한다.
   내장/별도 파일의 직렬화 hash는 다를 수 있어 값도 비교한다. 현재 두 소스의
   129개 텐서 값은 전부 일치한다. 기존 변환 보고서에 기록된 소스를 유지하며,
   과거 legacy 실행 파일 회수를 조건으로 두지 않는다.
3. dtype 미보존: convert_hash_embeddings_to_fused()가 fused hash embedding을
   기본 fp32 torch.zeros()로 새로 할당해 원본(bf16일 경우) 텐서를 조용히
   upcast한다 → 원본 텐서 dtype으로 할당하도록 수정. 이것은 A-7-2의
   "설명되지 않은 dtype 변환 금지"의 직접 적용 대상이다
4. 메모리: load_file()로 메인 가중치 전체 + entropy 전체 로드, fp32 fused
   hash(500,002 × 6 × hidden × 4B ≈ 11GiB) 추가 할당, 단일 save_file 저장
   → RAM 16GB인 gsm에서는 실행 불가. (a) host RAM을 사전 측정한 itcerdo
   (또는 neuron 로그인 노드)에서 실행하거나, (b) safe_open() 텐서 단위
   스트리밍 + max_shard_size 분할 저장으로 수정. 초기에는 (a)로 진행하고
   (a)마저 부족하면 (b)를 구현한다. "1B 규모이므로 RAM 제약 없음"은 틀린
   판단이었다 — hash embedding이 파라미터 수 대비 메모리를 지배한다
5. tokenizer 한도: create_tokenizer_config()가 config.get("max_seqlen", 1024)로
   model_max_length를 쓰며, merged config에 max_seqlen이 없으면 1024가 된다
   → max_position_embeddings 기반으로 수정하고, 변환 직후 A-7-2에서
   model_max_length ≥ 2048과 truncation=False를 검사
6. BOS/EOS 처리: tokenizer_config의 add_bos_token/add_eos_token 값은 실제
   삽입 동작의 증거가 아니다. upstream tokenizer.json의 post-processor는
   BOS만 삽입할 수 있으므로 실제 반환 ID를 검사한다. B-1은 본문을
   add_special_tokens=False로 인코딩하고 학습열에 BOS/EOS를 각 1회 명시적으로
   추가한다. 생성 prompt에는 BOS만 추가하며 EOS를 넣지 않는다.
   설정값·post-processor·실제 ID의 관계와 검증 결과를 변환 보고서에 기록한다
```

**A-7-4: 실행 구현과 연구 주장 범위**

### B-1. 데이터 어댑터

**제공 데이터 유지 원칙 (2026-09-14 사용자 확정)**: train/validation/test는

### B-2. 학습 루프

**구현 결정 (2026-09-16)**: `blt_hf/train.py`의 manual loop + DDP.
실행 명령과 재개 절차의 정본은 `blt_hf/NEURON.md`다.

본 절의 모든 optimizer/backward 작업은 neuron에서만 실행한다. itcerdo 5090은
구동·가중치·마스크 검사·forward 시간 측정 전용이다.

1. 원본·변환 artifact와 동일하게 main 파라미터·gradient·Adam 상태·연산을 BF16으로
   유지하고 entropy도 BF16으로 고정한다. dtype 불일치는 즉시 실패하며 학습 전 실제
   A100 메모리 smoke가 필요하다. 2026-09-17 이전 FP32 smoke는 이 조건의 검증이 아니다.
2. rank당 무패딩 1개, DDP `no_sync()` 누적, 실제 supervised token의 전역 평균 loss.
   마지막 배치를 버리지 않고 남는 rank는 zero-loss 동기화만 수행한다.
3. 전체 validation을 rank별로 나눠 합산한다. 부분 validation 점수로 best를 갱신하지 않는다.
4. checkpoint는 불변 step directory의 `model.safetensors`, `training.pt`,
   `checkpoint.json`이다. optimizer·rank별 RNG·epoch/다음 배치·manifest를 저장하고
   `latest.json`/`best.json`으로 참조한다. LR은 복원한 global step과 고정 schedule로 계산한다.
5. `--signal=B:TERM@300` 및 남은 시간을 감지해 step 경계에서 저장한다.
   동일 run·코드·데이터·환경·GPU 수로 사용자가 명시적으로 재개한다.
6. AdamW (0.9, 0.95), eps 1e-8, wd 0.1, 1차원 bias/norm decay 제외.
   다음 사이클은 LR 1e-5, effective batch 32, 10 epoch, 전체 update의 5% warmup을 사용한다.
   모든 epoch checkpoint를 보존하고 동일한 전체 validation 생성 조건의 GLEU로 최종
   checkpoint를 선택한다. test는 선택에 사용하지 않는다. seed 0으로 전체 파이프라인을
   확인한 뒤 seed 1·2를 별도 RUN_ID로 반복한다.
   2026-09-24에는 본 사이클에 앞서 native 2 epoch의 통합 시험을 별도 RUN_ID로 수행한다.
   A100 4GPU 학습 job의 각 rank가 매 epoch 전체 validation 생성을 분담하고 GLEU로
   checkpoint를 선택한다. 첫 시험은 beam1로 시간·메모리를 실측하며 M2는 선택에 쓰지
   않는다. 결과에 따라 beam4/10 epoch 실행을 결정한다. 명령은 `blt_hf/NEURON.md`를 따른다.
7. 가중치·attention mask 검사 증거와 학습·평가 실행 상태를 각각 기록한다.
   원본 BLT 수치 동질성 게이트는 없다.

```python
    num_beams: int = 4
    length_penalty: float = 1.0
    batch_size: int = 8
    use_cache: bool = False    # A-6 결과에 따라 기본값 결정

def build_prompts(tok, sources: list[str], cfg) -> BatchEncoding:
    # source+SEP를 add_special_tokens=False로 인코딩한 뒤 BOS를 1회 붙인다.
    # prompt = [BOS] source SEP. EOS나 target용 BOS를 삽입하지 않는다.
    # truncation 금지. 실측 최대 prompt=694; 초과 시 길이와 sample ID를 출력하고 실패.
    # prompt_len + max_new_bytes <= max_sequence_bytes를 강제
    # left-padding 설정 확인: decoder-only 생성은 tok.padding_side="left"가 표준.
    #   BLT patcher가 left-padding과 상호작용하는 방식을 반드시 확인하고
    #   (padding 바이트가 patch 경계를 오염시키면 attention_mask로 차단되는지)
    #   문제 시 A-4에서 검증한 pad-aware 경로 또는 무패딩 동일길이 batch로 대체한다.

def generate_batch(model, tok, sources, cfg) -> list[str]:
    # tok → model.generate(input_ids, attention_mask,
    #        max_new_tokens=cfg.max_new_bytes, num_beams=cfg.num_beams,
    #        length_penalty=cfg.length_penalty, do_sample=False,
    #        use_cache=cfg.use_cache, eos_token_id=...)
    # 출력에서 prompt 제거 → UTF-8 decode(errors 정책 명시) → strip
```

**테스트** — `tests/test_hf_generation.py`

```text
- separator 보존: 극단적으로 긴 source에서도 prompt가 SEP로 끝남
- 입력 절단 0건 및 prompt+max_new_bytes <= 2048 fail-fast
- batch 불변성: 동일 문장을 batch=1과 batch=8(다른 문장과 혼합)로 생성 → 동일 출력
- beam=1 vs num_beams=1 greedy 경로 일치
- EOS 조기 종료, 빈 출력, invalid UTF-8 방어
- (A-6에서 cache 정상이면) use_cache True/False 출력 일치
```

batch 불변성이 깨지는 흔한 원인: left-padding 처리, patcher의 padding 반응,
fp16 비결정성. 깨지면 원인을 분리해 기록하고, 허용 오차(출력 문자열 기준
완전 일치)를 통과할 때까지 수정한다.
