### A-2. 모델 로드 및 생성 sanity check

**작업 내용**

`blt_hf_checks/check_load_generate.py` 작성:

```python
import torch
from transformers import AutoTokenizer, BltForCausalLM

MODEL_ID = "itazap/blt-1b-hf"
PROMPTS = [
    "My name is",
    "안녕하세요. 오늘 날씨가",
    "다음 문장을 교정하세요:",   # GEC 유사 프롬프트
]

def main():
    tok = AutoTokenizer.from_pretrained(MODEL_ID)
    model = BltForCausalLM.from_pretrained(
        MODEL_ID, torch_dtype=torch.bfloat16, device_map="cuda",
        attn_implementation="eager",   # 1차: eager로 correctness 확인
    )
    model.eval()
    for p in PROMPTS:
        inputs = tok(p, return_tensors="pt").to(model.device)
        with torch.no_grad():
            out = model.generate(**inputs, max_new_tokens=64,
                                 do_sample=False, use_cache=False)
        print(f"--- prompt: {p!r}")
        print(tok.decode(out[0]))

if __name__ == "__main__":
    main()
```

**실행 작업**

1. eager로 실행 → 출력이 유의미한 텍스트인지, 한국어 출력이 깨진 UTF-8을 포함하지 않는지 확인.

2. `attn_implementation="sdpa"`로 재실행 → eager와 greedy 출력 token ID가 동일한지 비교 (`torch.equal`). 다르면 그 차이를 기록하고 이후 실험은 한 가지 구현으로 고정한다.

3. bf16 vs fp32 greedy 출력 비교 (V100 사용 가능성 대비 fp16도 확인).

**완료 기준**: eager/sdpa 양쪽에서 유효한 UTF-8 생성, greedy 출력 일치 여부 문서화.

### A-4. Attention mask 의미 검증 (핵심 검증 2)

HF local encoder/decoder가 원본의 local block-causal(sliding window + EOS
segment 격리)을 보존하는지 확인한다. legacy 체크포인트가 full-causal
fallback으로 학습된 전례가 있으므로, 이번에는 반드시 코드 레벨에서 확정한다.

**작업 내용**

1. **코드 리딩**: `transformers/models/blt/modeling_blt.py`에서
   - local encoder self-attention의 마스크 생성 함수
   - local decoder self-attention의 마스크 생성 함수
   - cross-attention(byte↔patch)의 마스크 생성 함수
   를 찾아 각각의 허용 조건을 수식으로 정리해 `blt_hf/NOTES.md`에 기록.
   (sliding window 파라미터가 config에 있는지, EOS segment 분리가 구현되어
   있는지, 아니면 단순 causal인지.)

2. **단위 테스트**: `blt_hf_checks/check_attention_mask.py`

```python
# 소형 인공 시퀀스 (예: 길이 24, 중간에 EOS 2개 삽입)로 마스크 텐서를 직접 추출
# 검사 항목 (원본 BLT의 의미 기준):
#   - 미래 위치 차단 (causal)
#   - window(W) 밖 과거 위치 차단
#   - EOS 이전 query가 EOS 이후 key를 참조하지 않음 (역방향도)
#   - batch별 segment 경계 독립성
# HF 구현이 window/segment를 지원하지 않으면 그 사실 자체를 기록
```

3. **판정 분기**:
   - HF가 원본 의미를 보존 → 통과, 다음 단계로.
   - HF가 단순 causal만 구현 → 사전학습 가중치도 HF 변환 시 같은 코드로
     검증되었을 것이므로, "HF 세계 안에서의 self-consistency"는 성립한다.
     이 경우 (i) 원본 논문과의 어텐션 의미 차이를 논문에 명시하고,
     (ii) Transformers upstream 이슈를 확인/보고하고,
     (iii) 실험은 HF 구현 그대로 진행한다. 자체 마스크 패치는 하지 않는다
     (upstream과의 divergence가 유지비용 > 이득).

**완료 기준**: 마스크 허용 조건이 수식으로 문서화되고, 단위 테스트가 그
조건을 통과하며, 원본과의 차이(있다면)가 명시됨.

### A-5. 학습 forward 검증 (핵심 검증 3)

**작업 내용**

`blt_hf_checks/check_train_forward.py`:

```python
# 1) tiny overfitting 테스트
#    - GEC 예제 4개를 배치로 구성 (Phase B의 data_adapter 프로토타입 사용)
#    - labels에서 source 부분 -100 마스킹 (prefix-LM)
#    - AdamW lr=1e-4로 200 step 학습 → loss가 ~0 근처로 수렴하는지
# 2) gradient 흐름 검사
#    - local encoder / global / local decoder 각 파라미터 그룹의
#      grad norm이 0이 아닌지 (cross-attention 경계 확인)
# 3) patch_lengths 입력 경로 확인
#    - forward가 patch_lengths를 받는지 / 내부에서 자동 계산하는지
#    - 자동 계산이면 batch 내 padding이 patch 경계를 오염시키지 않는지
#      (attention_mask 전달 시 padding 위치 entropy 처리 확인)
```

**실행 작업**: GPU 1장, 10분 이내. loss 곡선과 grad norm을 stdout에 출력하고
스크린샷/로그 보존.

**완료 기준**: 4예제 overfit 성공(loss < 0.05), 세 컴포넌트 모두 grad 흐름,
padding 처리 방식 문서화.

### A-6. KV cache 동작 probe (P3a 판정 입력)

**작업 내용**

`blt_hf_checks/check_cache_probe.py`:

```python
# 동일 프롬프트에 대해:
#   out_nc = model.generate(..., use_cache=False, do_sample=False)
#   out_c  = model.generate(..., use_cache=True,  do_sample=False)
# 검사:
#   (a) use_cache=True가 예외 없이 실행되는가
#   (b) 출력 token ID가 use_cache=False와 완전 일치하는가
#   (c) 긴 생성(512 bytes)에서 wall-clock 비교
# 세 결과를 JSON으로 저장 → P3a 트리거 판정 자료
```

**고장 깊이 판정** (probe 결과에 반드시 포함):

```text
(가) 정상: use_cache=True가 동작하고 출력이 no-cache와 일치
     → cache 사용을 기본값 후보로 검토. P3a 불필요
(나) 얕은 고장: cache 로직은 존재하나 generate 경로에서 비활성화되어 있거나
     사소한 버그 (코드 리딩으로 원인 특정 가능)
     → P1 범위 내에서 수정한다: modeling_blt.py를 blt_hf/patched/로 복사
       (또는 BltForCausalLM 서브클래싱)해 자기 네임스페이스에서 명시적으로
       관리. 원본 대비 diff를 NOTES.md에 기록, no-cache 출력과의 parity
       테스트 필수, upstream 이슈/PR 지향. site-packages 직접 편집은 금지
(다) 깊은 부재: patcher/encoder/global/decoder의 증분 상태 관리 자체가 없음
     → "수정"이 아니라 설계·구현의 영역. P3a 스코프로 이관
```

얕은 수정과 P3a는 대립 선택지가 아니라 같은 스펙트럼이며, 이 probe가 고장의
깊이를 판정한다.

**완료 기준**: (a)(b)(c) 결과 + 깊이 판정((가)/(나)/(다))이
`blt_hf_checks/results/cache_probe.json`으로 저장됨. (나)일 경우 patched
